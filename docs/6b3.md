## 1. Overview and Purpose

Phase 6B.3 implements the grounded reasoning and prompt synthesis layer of the Krishna AI RAG system. Building directly upon Phase 6B.1 (database foundation) and Phase 6B.2 (semantic retrieval), this phase transforms retrieved Bhagavad Gita verses into structured, compassionate, and scripture-grounded responses.

**Execution Boundary:**
- Reasoning and generation **only**.
- **No** HTTP API Route Handlers (`app/api/krishna/route.js` belongs to Phase 6B.4).
- **No** UI or chat front-end.
- **No** conversation memory or multi-turn history persistence.
- **No** streaming implementation.

---

## 2. Reasoning Architecture

The pipeline follows a clean separation of concerns:

```
User Question + Retrieved Verses [Phase 6B.2]
       │
       ▼
1. Zero-Retrieval Guard [lib/krishna/generator.js]
   (If 0 verses retrieved, immediately returns safe ungrounded notice without calling LLM)
       │
       ▼
2. Prompt Construction [lib/krishna/prompt.js]
   • Encapsulates retrieved verses in deterministically delimited <GITA_CONTEXT>
   • Sets compassionate spiritual companion persona
   • Forbids pretending to be God or claiming divine supernatural authority
   • Instructs model to cite ONLY supplied verses with exact UUIDs & references
   • Requires raw JSON output matching strict schema
       │
       ▼
3. Gemini Generative Call [lib/krishna/generator.js]
   • Primary Model: gemini-flash-lite-latest (fast, stable, low latency)
   • Fallback Model: gemini-3.1-flash-lite-preview (automatic fallback on 503 spikes)
   • Generation Config: responseMimeType="application/json", temperature=0.7
       │
       ▼
4. JSON Parsing & Code Fence Stripping
       │
       ▼
5. Grounding Validation & Citation Enforcement [lib/krishna/generator.js]
   • Filters/rejects any cited UUID not present in retrievedVerses
   • Filters/rejects any chapter.verse reference not present in retrievedVerses
   • Validates non-empty answer string
       │
       ▼
Validated Structured Response { answer, citedVerseIds, citations, meta }
```

## 4. Prompt Construction & Gita Context Formatting

### 4.1 Persona & Behavioral Boundaries
- **Spiritual Companion:** Speaks as a wise, empathetic companion inspired by Krishna's teachings, rather than claiming supernatural godhood.
- **Natural Wisdom:** Synthesizes teachings into conversational guidance rather than dumping disconnected verse fragments.
- **Strict Citation Rules:** Strictly constrained to cite only verses supplied in `<GITA_CONTEXT>`.
- **System Secrecy:** Forbids mentioning vector databases, embeddings, similarity scores, retrieval functions, or prompt guidelines.

### 4.2 Delimited Context Format
```
<GITA_CONTEXT>
[Verse 1]
ID: 686f63bc-f057-4dce-9018-c6e358fed46b
Reference: Bhagavad Gita Chapter 18, Verse 30 (Moksha Sanyaas Yoga)
Translation: The intellect which knows the path of work and renunciation...
Commentary: ...
Practical Insight: ...

[Verse 2]
ID: 4082ec57-a996-41ec-b575-8952d59816b5
Reference: Bhagavad Gita Chapter 16, Verse 2 (Daivasura Sampad Vibhaga Yoga)
Translation: Harmlessness, truth, absence of anger...
</GITA_CONTEXT>
```

## 5. Structured Response & Grounding Validation

### 5.1 JSON Output Schema
```typescript
interface KrishnaAIResponse {
  answer: string;
  citedVerseIds: string[]; // UUIDs of verses explicitly cited in the answer
  citations: Array<{
    chapter: number;
    verse: number;
  }>;
  meta: {
    isGrounded: boolean;
    zeroRetrieval: boolean;
    model: string;
    retrievedCount: number;
    citedCount: number;
    generatedAt: string;
  };
}
```

### 5.2 Citation Enforcement Rule
Post-generation validator (`validateAndEnforceGrounding`):
- Checks all UUIDs in `citedVerseIds` against the retrieved set: any unknown or hallucinated ID is immediately stripped.
- Checks all `(chapter, verse)` pairs in `citations`: any pair not in the retrieved set is stripped.
- Ensures explicit verse citations can **never** reference verses outside the retrieved context.

## 6. Error Classification & Security

All raw provider errors are intercepted by `classifyGeminiError()` before propagating to callers. Under **no** circumstances are API keys or authorization headers included in error messages or logs.

| Error Condition | Internal Code | User-Facing Safe Message |
|---|---|---|
| Missing `GEMINI_API_KEY` | `MISSING_API_KEY` | `"Gemini API key is not configured."` |
| Invalid API key / 401 / 403 | `AUTH_FAILED` | `"Gemini authentication failed. Please check the configured API key."` |
| 429 / Quota / Rate limit | `RATE_LIMIT_EXCEEDED` | `"AI service rate limit or quota exceeded."` |
| 503 / Service Unavailable | `SERVICE_UNAVAILABLE` | `"AI service is temporarily unavailable. Please try again shortly."` |
| General network / socket | `GENERATION_FAILED` | `"AI generation failed. Please try again."` |

---

## 7. Zero-Retrieval Safe Behavior

When retrieval produces zero candidate verses (`retrievedVerses.length === 0`):
- The model is **not** invoked.
- Zero API quota is consumed.
- The module returns:
  ```json
  {
    "answer": "No sufficiently relevant Bhagavad Gita context was found for this question. Please consider rephrasing your question or exploring another topic.",
    "citedVerseIds": [],
    "citations": [],
    "meta": {
      "isGrounded": false,
      "zeroRetrieval": true,
      "model": "none",
      "retrievedCount": 0,
      "citedCount": 0
    }
  }
  ```

## 9. What is Intentionally Deferred to Phase 6B.4

To strictly maintain architectural modularity, Phase 6B.3 does **not** implement:
- **API Route:** `app/api/krishna/route.js` (HTTP request handling, authentication cookies, user-level rate limits).
- **UI:** Krishna chat conversation drawer or message timeline.
- **Chat History & Persistence:** Writing messages to the `conversations` and `messages` tables.
- **Streaming:** SSE / chunked streaming responses.
- **Production Retry/Backoff Orchestration:** Client-facing retry strategies.
