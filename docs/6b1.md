## 2. What Was Implemented

### 2.1 `match_verses()` PostgreSQL RPC Function

A `security definer` RPC function that performs semantic vector search over the existing `gita_verses` table using the pre-computed 768-dimensional embeddings.

**Signature:**
```sql
public.match_verses(
  query_embedding  vector(768),
  match_threshold  float    default 0.0,
  match_count      integer  default 5,
  filter_themes    text[]   default null,
  filter_chapter   integer  default null
)
```

**Returns** one row per matching verse:

| Column | Type | Source |
|---|---|---|
| `id` | uuid | `gita_verses.id` |
| `chapter_number` | integer | `gita_verses.chapter_number` |
| `chapter_name` | text | `gita_chapters.name_translated` (falls back to `name`) |
| `verse_number` | integer | `gita_verses.verse_number` |
| `sanskrit_text` | text | `gita_verses.sanskrit_text` |
| `transliteration` | text | `gita_verses.transliteration` |
| `translation` | text | `gita_verses.translation` |
| `commentary` | text | `gita_verses.commentary` |
| `practical_insight` | text | `gita_verses.practical_insight` |
| `similarity` | float | Computed: `1.0 - (embedding <=> query_embedding)` |

**Key implementation details:**

- Uses the **existing** `gita_verses.embedding` column (768-dim, gemini-embedding-001) and the **existing** `gita_verses_embedding_ivfflat_idx` index. Does not generate embeddings itself.
- `ORDER BY gv.embedding <=> query_embedding ASC` — results are returned closest first, allowing the ivfflat index to return candidates in distance order without a full-table sort.
- `match_threshold` is a minimum cosine **similarity** (0.0 – 1.0). Internally it is expressed as a maximum cosine **distance** in the `WHERE` clause:

  ```
  similarity ≥ match_threshold  ⟺  distance ≤ (1.0 − match_threshold)
  ```

  This form (`gv.embedding <=> query_embedding <= (1.0 - match_threshold)`) allows the ivfflat index to prune candidates early, before computing the similarity value for each row.

#### 2.1.1 Theme Filtering (`filter_themes`)

Restricts results to verses linked to one or more matching themes via the `verse_themes` join table.

- **No slug column exists** in the `themes` table. The canonical identifier is `name` (text, unique).
- `filter_themes` accepts an array of theme name strings, matched case-insensitively.
- Both the display name (`"Self Control"`) and its hyphenated form (`"self-control"`) are matched, covering all canonical theme names defined in `lib/gita/constants.js`.
- If `filter_themes` is `null` or an empty array, no theme restriction is applied.

#### 2.1.2 Chapter Filtering (`filter_chapter`)

Restricts results to a specific Bhagavad Gita chapter by `chapter_number` (integer, 1–18). If `null`, no chapter restriction is applied.

#### 2.1.3 Permissions

Execution is granted to `authenticated` users only, consistent with all existing Gita table RLS policies established in migration 6A.1. Anonymous callers cannot invoke this function.

```sql
grant execute on function public.match_verses(vector(768), float, integer, text[], integer)
  to authenticated;
```

### 2.2 `conversations` Table

Stores conversation threads between a user and the Krishna AI.

| Column | Type | Notes |
|---|---|---|
| `id` | uuid | Primary key, `gen_random_uuid()` |
| `user_id` | uuid | FK → `auth.users(id) ON DELETE CASCADE`, not null |
| `title` | text | Not null, defaults to `'New Conversation'` |
| `created_at` | timestamptz | Not null, defaults to `now()` |
| `updated_at` | timestamptz | Not null, defaults to `now()`, auto-maintained by trigger |

Index: `idx_conversations_user_updated` on `(user_id, updated_at DESC)` — supports efficient retrieval of a user's most recently active conversations.

#### `updated_at` Trigger

Function `public.update_conversations_updated_at()` and trigger `tr_conversations_updated_at` (BEFORE UPDATE, FOR EACH ROW) automatically set `updated_at = now()` on every update to a conversation row.

### 2.3 `messages` Table

Stores individual message turns within a conversation thread.

| Column | Type | Notes |
|---|---|---|
| `id` | uuid | Primary key, `gen_random_uuid()` |
| `conversation_id` | uuid | FK → `public.conversations(id) ON DELETE CASCADE`, not null |
| `role` | text | Not null. CHECK constraint: must be `'user'`, `'assistant'`, or `'system'` |
| `content` | text | Not null. The message body |
| `cited_verse_ids` | uuid[] | Array of `gita_verses.id` UUIDs referenced in the response. Defaults to `{}`. Stores citations without duplicating verse text |
| `retrieval_meta` | jsonb | Metadata about the retrieval pass that produced this message (e.g. similarity scores, filters used). Defaults to `{}`. Reserved for future retrieval orchestration |
| `is_flagged` | boolean | Safety/moderation flag. Defaults to `false`. Reserved for future policy layer |
| `created_at` | timestamptz | Not null, defaults to `now()` |

Index: `idx_messages_conversation_created` on `(conversation_id, created_at ASC)` — supports chronological message fetching within a conversation.

**Allowed `role` values:**
- `'user'` — message sent by the seeker
- `'assistant'` — response generated by Krishna AI
- `'system'` — system-level instruction or context turn

### 2.4 Row Level Security

RLS is enabled on both `conversations` and `messages`. All policies restrict access to `authenticated` users only. Anonymous users cannot read, insert, update, or delete any rows.

#### `conversations` policies

| Operation | Policy | Condition |
|---|---|---|
| SELECT | Users can view their own conversations | `auth.uid() = user_id` |
| INSERT | Users can create their own conversations | `auth.uid() = user_id` |
| UPDATE | Users can update their own conversations | `auth.uid() = user_id` (USING + WITH CHECK) |
| DELETE | Users can delete their own conversations | `auth.uid() = user_id` |

#### `messages` policies

Messages have no `user_id` column. Access is verified through conversation ownership: a user may only access messages that belong to a conversation they own.

| Operation | Policy | Condition |
|---|---|---|
| SELECT | Users can view messages from their own conversations | Conversation's `user_id = auth.uid()` |
| INSERT | Users can insert messages into their own conversations | Conversation's `user_id = auth.uid()` |
| UPDATE | Users can update messages in their own conversations | Conversation's `user_id = auth.uid()` (USING + WITH CHECK) |
| DELETE | Users can delete messages in their own conversations | Conversation's `user_id = auth.uid()` |
