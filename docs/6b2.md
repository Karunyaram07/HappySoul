## 1. Overview and Purpose

Phase 6B.2 bridges the database foundation established in Phase 6B.1 and the future AI response generation. It implements the application-level retrieval layer that:

1. Takes an externally provided Supabase client and a natural language user query.
2. Generates a 768-dimensional query vector using the canonical embedding provider.
3. Calls the Supabase `match_verses()` RPC function.
4. Provides graceful fallback when theme filters yield zero results (`fallbackWithoutThemes`).
5. Normalizes and returns clean, structured verse candidates ranked by semantic similarity.

**Execution Boundary:**
- Retrieval **only**.
- **No** Gemini chat/answer generation is implemented.
- **No** RAG prompt synthesis is performed.
- **No** UI or HTTP Route Handlers are added.

## 2. Retrieval Architecture

The retrieval flow follows a strict, single-path architecture with dependency-injected data access:

```
Caller (Route Handler / Test Runner)
  │ Passes initialized Supabase client (User session or Service role)
  ▼
retrieveRelevantVerses(supabase, query, options) [lib/krishna/retrieval.js]
  │
  ├── 1. Validation & Sanitization (query string, emptiness, max length <= 1000)
  │
  ├── 2. generateQueryEmbedding() [lib/embeddings/provider.js]
  │        • Model: gemini-embedding-001
  │        • TaskType: RETRIEVAL_QUERY
  │        • Dimensions: 768
  │
  ├── 3. match_verses() RPC [Supabase Postgres pgvector]
  │        • Parameters: query_embedding, match_threshold, match_count, filter_themes, filter_chapter
  │        • Index: ivfflat cosine distance
  │
  ├── 4. Theme Fallback Logic (if filterThemes yielded 0 rows & fallback enabled)
  │        • Re-executes match_verses() without filter_themes
  │        • Marks meta.usedThemeFallback = true
  │
  ├── 5. Normalization (snake_case DB columns → camelCase application fields)
  │
  ▼
RetrievalResult { query, verses, count, meta }
```

### Module Boundary
[`lib/krishna/retrieval.js`](file:///a:/June2026/happy-soul/lib/krishna/retrieval.js) is the sole entry point for all Bhagavad Gita semantic verse retrieval. It does **not** create Supabase clients internally, ensuring full flexibility across Next.js Route Handlers (user session context) and background/scratch jobs (service-role context).

## 4. Function Signature & Settings

### 4.1 Signature
```javascript
retrieveRelevantVerses(supabase, query, options)
```

- **`supabase`**: Active Supabase client instance with `.rpc()` capability.
- **`query`**: Natural language user inquiry (string, 1–1000 characters).
- **`options`**: Optional configuration overrides.

### 4.2 Configurable Defaults (`RETRIEVAL_DEFAULTS`)

| Setting | Default Value | Rationale |
|---|---|---|
| `MATCH_THRESHOLD` | `0.5` | Minimum cosine similarity. Validated empirically: meaningful Gita queries score between `0.52` and `0.70`, whereas irrelevant noise queries score strictly below `0.50` (max noise: `0.4964`). |
| `MATCH_COUNT` | `5` | Up to 5 verses returned. Balances grounding context richness with prompt token budgets. |
| `MAX_QUERY_LENGTH` | `1000` | Input character upper limit preventing prompt injection or excessive payload tokens. |
| `fallbackWithoutThemes` | `true` | When theme filtering produces 0 candidates (e.g., empty `themes` table or overly narrow tag), automatically retries without theme filter to prevent empty AI context. |

## 5. Result Structure

The module outputs structured JavaScript objects with camelCase keys:

```typescript
interface RetrievalResult {
  query: string;
  verses: RetrievedVerse[];
  count: number;
  meta: {
    matchThreshold: number;
    matchCount: number;
    filterThemes: string[] | null;
    filterChapter: number | null;
    fallbackWithoutThemes: boolean;
    usedThemeFallback: boolean;
    embeddingModel: string;          // e.g. "gemini-embedding-001"
    embeddingDimensions: number;     // 768
    embeddingGeneratedAt: string;    // ISO timestamp
  };
}

interface RetrievedVerse {
  id: string;
  chapterNumber: number;
  chapterName: string;
  verseNumber: number;
  sanskritText: string;
  transliteration: string;
  translation: string;
  commentary: string;
  practicalInsight: string | null;
  similarity: number;
}
```

## 6. Theme Fallback Mechanism

Since the database `themes` table currently contains no seed rows (established in Phase 6B.1):

1. If `filterThemes` is passed (e.g. `["Peace"]`), the initial RPC call returns 0 rows.
2. If `options.fallbackWithoutThemes !== false` (default: `true`), the module logs the condition and immediately re-executes `match_verses()` without the `filter_themes` parameter.
3. The result includes `meta.usedThemeFallback = true`, informing the caller that general semantic search was used.
4. If `options.fallbackWithoutThemes === false`, fallback is skipped and an empty result is returned with `meta.usedThemeFallback = false`.
